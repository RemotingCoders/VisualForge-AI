## Verified API reference (dev.meta.ai/docs, pasted by Damian 2026-10-28)
- **Base URL:** `https://api.meta.ai/v1` · **Auth:** `Authorization: Bearer $MODEL_API_KEY` (key set by Damian in `.env.local`, never via chat)
- **Model IDs:** `muse-image-1.0`, `sam-3.1`, `muse-spark-1.3`
- **Muse Image edit:** `POST /v1/images/edits` `{model, prompt, images:[{image_url:"data:image/...;base64,..."}], n}` — **no mask parameter in docs.** Strategy (approved): crop the SAM region + margin → edit crop → composite back with feathered mask → real differences from pixel diff. Spike also tests whether a full-image edit respects the untouched rest.
- **SAM 3.1 segment:** `POST /v1/responses` `{model:"sam-3.1", input:[{type:"message",role:"user",content:[{type:"input_text",text:"<ONE short noun phrase>"},{type:"input_image",image_url}]}], stream:true, metadata:{include_confidence:"true", mask_encoding:"one_bit"}}`. One concept per request (comma lists return zero matches; no negation/questions). SSE events `response.output_text.delta`; zero matches = empty output, valid.
- **SAM output grammar:** `<0f>0<|box;x1=..;y1=..;x2=..;y2=..;w=..;h=..[;c=0..1]|><|mask;x=0;y=0[;c=..];data=H,W,ENC+payload|>` — box in source pixels, `data=` is **H (rows) first**, ENC `~`=lossless / `!`=one_bit, payload **base85**. Object ids stable but sparse. Implemented: [meta.ts](../src/lib/engine/meta.ts) `parseSamOutput` (fields parsed by key), unit-tested with fake fetch — no paid calls in tests.
- **SAM mask → raster:** `decodeMaskToRaster` exists ONLY in the official client libraries (`@meta-sam/parser` ≥ 0.0.13 / `meta-sam-parser` ≥ 0.0.6; details on `/docs/sam/client-libraries`, **not yet pasted**). Our `decodeMaskToRaster` stays a loud stub — the pipeline does not need it: real masks/bboxes are measured from pixel diff, SAM boxes seed the crop.
- **Muse Spark structured output:** Responses API → `text:{format:{type:"json_schema", name, schema, strict:true}}` (Chat Completions uses `response_format` instead; a parameter from the other endpoint does not configure it). Result is a JSON string in `output_text`. Schemas must satisfy the strict subset: root object, `additionalProperties:false`, `required` lists every property, no recursion, depth ≤ 10. Implemented: `sparkStructured` + `SPARK_SCHEMAS` in [providers.ts](../src/lib/engine/providers.ts) (moderation / concepts / plan / verification).
- **Muse Spark scene → SAM workflow (per docs):** Spark lists segmentable concepts → SAM segments each concept. Implemented in `MetaProvider.segment` (max 8 concepts).
- **Still unverified (not guessed):** Muse Image *generation* request shape (scene generation stays `MetaNotConfiguredError`); Spark image parts use the verified Responses `input_image` shape. ~~Muse Image edit response shape~~ → verified call 3/6: `data[0].b64_json`, 1600×1600 WebP output.

## One-pass mode (game path, integrated 2026-10-30)
One full-image Muse call with a generic N-differences prompt (explicit variety: add a detail, remove a part, add an object, change a color, swap an element) → global alignment compensation (`estimateAlignment`) → component extraction → compose ONLY the chosen components over the ORIGINAL (everything else pixel-identical) → re-measure mask/bbox/centroid → ONE batched Muse Spark review of the N crop pairs (description + verdict each). If it delivers fewer than N: a second pass asking only for the missing count, then the crop pipeline tops up. QC mode stays on crops. Per-pass console log: alignment, every component/discarded component with area + amplitude + reason, which were chosen, and Spark's verdict per difference; final summary line: mode used, calls per model (muse/spark/sam), seconds per stage.

**Deviation from the originally requested separation thresholds (with data):** dual amplitude thresholds (seed ≥35 / grow ≥14 / mean ≥25) provably cannot separate the edits from re-render noise on the spike pair — petal-vein noise reaches mean amplitude 27–45 over huge areas, while the vanished bud's max amplitude is only ~82 (noise p99 49–66). The calibrated criterion instead uses a **low-pass difference** (box-blur both images r=3, diff the blurred versions: texture rearrangement cancels, solid edits persist), **new edges** (gradient of the edited image that the original doesn't have), and **original texture** (real edits sit on smooth areas; noise lives on textured ones). A blob is real iff `meanLp ≥ 25` OR (`meanNewEdge ≥ 15` AND `meanTex ≤ 25`); area 24px–6%. Thresholds are locked by `tests/onepass-calibration.test.ts` on the saved one-pass spike pair (`debug-runs/muse-one-pass-2026-10-30T21-10-54-350Z.png` vs `test.jpeg`): exactly 3 components — vanished bud 2561px @ (259,48) 70×60, ladybug 670px @ (457,481) 28×32, droplet 96px @ (395,110) 16×17. The raw Muse full-image output is NEVER published — only its extracted components composited over the original.

**One change must never count as several (moon-flag fix, 2026-11-01):** a single added flag once shipped as THREE differences (cloth, pole, base) because the thin pole split the extraction into separate components and Spark described each part with the same phrase at a different location. Four layers now prevent it: (1) extraction groups candidate pixels through their STRONG core (`lp ≥ coreLp`) dilated 10 px — a thin connector joins its ends, weak re-render islands never chain (the calibrated blob criteria and the stored, undilated measured mask are unchanged); (2) the batched-review schema carries `sameChangeAs` (index of an earlier pair showing parts of the same single change, or −1) and parts Spark so marks are fused (union mask/box, larger-area description) instead of counted; (3) server-side description dedupe normalizes away location phrases ("at the…", "next to…", "in front of…", "on the left/right…") — close duplicates fuse, far ones are discarded as phantoms (the earlier flip-flops case), cross-pass duplicates still discard; (4) after review, a **minimum-separation merge** fuses any accepted differences — one-pass or crop path — whose boxes sit closer than 6 % of the image's smaller side. The one-pass prompt also tells Muse to spread differences across different areas, never two close to each other. Covered offline by `tests/merge.test.ts` (fake providers): three vertical components 5 px apart extract as one, three descriptions equal modulo location dedupe to one difference, `sameChangeAs` fusions lose no pixels.

**QC difficulty = inspector level (2026-11-01; floor semantics corrected 2026-11-02):** /qc has the same difficulty selector as /play (Easy/Medium/Hard, default Medium), sent as `difficulty` in `POST /api/generate` and passed to the QC planner. Semantics for defects: easy = large, clearly visible at normal viewing size, on the largest surfaces of the part, preferred minimum **measured** area 0.10 % of the image; medium = medium size anywhere, preferred minimum 0.05 %; hard = component-scale, no minimum (`QC_AREA_FLOOR` in [jobs.ts](../src/lib/server/jobs.ts)). The floor is a **priority, not a gate** (same rule as the game's one-pass floors): in both QC paths a below-floor defect is **held** — the one-pass path into the shared `heldBelowFloor` pool, the crop executor into `heldQcCandidates` (held *before* the Spark verify call, so no call is spent on it) — and once every candidate is exhausted the **best held defects deliver as the last resort** (one-pass: highest extraction score via `applyLastResort`; crops: largest measured area, pixels transplanted onto the current image, re-measured, and Spark-verified then if never verified) instead of failing with "no change survived". Three **consecutive** below-floor candidates **relax the floor one tier** for the rest of the job (easy → medium's 0.05 %, medium → none; logged), so a small-featured part does not burn paid calls chasing the floor; any acceptance resets the streak. For easy/medium the QC planner prompt adds the verbatim rule "defects must be clearly visible at normal viewing size, on the largest surfaces of the part", preferring the largest parts/surfaces of the piece, and for easy the planner prompt, the one-pass edit prompt and the crop edit prompt all ask for "a large, clearly visible defect covering a significant part of the surface, not a small mark". The difficulty is stored on the level (in-memory store + `visualforge_levels.difficulty`, migration `0007_level_difficulty.sql`, with the usual retry-narrower insert fallback on older databases) and surfaces in the gallery, in `GET /api/level` payloads and in the QC reveal, where /qc shows "Inspector level: Easy". Covered offline by `tests/qc-difficulty.test.ts` (fake providers + a fake fetch capturing the real planner prompt): crop-path hold-and-replace at medium and easy, the held last resort delivering a lone below-floor defect (verified only then), floor relaxation after three consecutive below-floor candidates, hard accepting a component-scale defect, the one-pass hold (a painted defect measuring 0.087 % is held at easy and delivers via the last resort when the count needs it, stays unpublished when it doesn't), the planner receiving the difficulty, the prompt rules (visibility rule for easy/medium, large-defect phrase for easy only), and the reveal exposing the stored level.

**QC defect hint — "What defects should appear?" (2026-11-02):** /qc has an optional free-text field sent as `defectHint` in `POST /api/generate` (QC mode only, max 300 characters — 400 beyond that; empty/absent is byte-identical to the previous behavior, prompts included). Inside the job the hint passes the SAME text moderation as themes (`moderateTheme`, before any planning/editing spend; a rejection fails the job with the moderation reason). The QC planner then receives the verbatim sentence "The inspector asked for these defects, in priority order: &lt;hint&gt;. Plan them first, mapped to the closest allowed defect types, on the parts where they physically make sense; only after them add other defect types if more are needed." and the one-pass QC prompt and each crop edit prompt append the same inspector sentence for their candidate. The hint steers planning/editing ONLY: defect descriptions and the Spark classification keep coming from what was measured, so the exported dataset reflects what actually landed in the image. The hint is stored on the level (`visualforge_levels.defect_hint`, migration `0008_level_defect_hint.sql`, same retry-narrower insert/select fallback) and shown in the gallery and in the QC reveal as "Requested: …". Covered offline by `tests/qc-defect-hint.test.ts` (fake providers + fake fetch): hint reaches the planner and its candidate order is the publish order, crop edit prompts carry the sentence, the one-pass prompt carries it, prompts without a hint are byte-identical (absent === empty) and game mode never gets the sentence, a moderation-rejected hint fails before the planner runs, the hint is stored and returned by `/api/qc-reveal`, and the route enforces the 300-character cap in QC mode only.

## Costs (updated 2026-11-02 — supersedes "see Meta dashboard" above)
The API still returns usage, not dollars — but the per-call dollar figures no longer come from the dashboard. Published prices (verified 2026-10-31 on [dev.meta.ai/docs/pricing-rate-limits](https://dev.meta.ai/docs/pricing-rate-limits)) live in [pricing.ts](../src/lib/engine/pricing.ts): Muse Spark $1.25/1M input + $4.25/1M output tokens (cached input $0.15/1M), computed per call from the response `usage`; SAM 3.1 $2.50 per 1,000 images ($0.0025 per call, one image each); Muse Image flat $0.01 per **generated** image. **Muse Image edits are priced differently (2026-11-02):** the page was re-read and lists **no per-token price for Muse Image at all** (only the flat $0.01; edit `usage` is returned "for reference"), while edits return 20k–28k input tokens and the Meta dashboard shows ≈ $0.50 per edit (~$122 over ~50 generated levels). Every `/images/edits` call is therefore costed with `MUSE_IMAGE_EDIT_USD_FALLBACK = 0.50` — an empirical constant calibrated against the dashboard, marked as such in the code — and `metaPost` also records input/output tokens per model into a running ledger ([spend.ts](../src/lib/server/spend.ts)) that each job diffs and logs at the end (`tokens: muse-image-1.0: N input / M output tokens · …`). `metaPost` writes the computed figure to `estimated_cost_usd` in `visualforge_ai_calls` on every call. Those rows feed the `VF_SPEND_CAP_USD`/`VF_SPEND_CAP_SINCE` judging-period budget: the accumulated sum **reprices historical edit rows** (logged at $0.01 before the fix) to the $0.50 fallback at read time — idempotently, since new rows already carry it — in both the database sum and the in-memory ledger. At the cap, every Meta-calling route answers 429 and only the free surfaces (gallery, stored levels, clicks, saved hints, exports) keep working. Public-demo access is one rule — `requireMetaAccess` ([access.ts](../src/lib/server/access.ts)) gates `/api/generate` and `/api/ai-inspect` whenever `VF_ACCESS_CODE` is set; `tests/spend.test.ts` walks `src/app/api` and fails any Meta-calling route that skips the gates, and covers the edit pricing, the historical repricing and the per-model token ledger.
